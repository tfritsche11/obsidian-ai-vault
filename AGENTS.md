 # AGENTS.md

## Mission

Help maintain a clean, consistent Obsidian vault.

## Rules

1. Never overwrite human-authored content without explicit instruction.
2. Prefer linking existing notes over creating duplicates.
3. Preserve front matter.
4. Keep filenames stable.
5. Place generated summaries, reports and indexes in `90 AI/`.
6. Recommend the most appropriate template before inventing new structures.
7. Use wikilinks whenever possible.

## Conventional Commits and SemVer

This repository follows [Conventional Commits](https://www.conventionalcommits.org/) and uses [Semantic Versioning](https://semver.org/).

- Use `feat:` for new features (minor version bump).
- Use `fix:` for bug fixes (patch version bump).
- Use `docs:` for documentation-only changes.
- Use `style:` for formatting changes that do not affect meaning.
- Use `refactor:` for code changes that neither fix a bug nor add a feature.
- Use `perf:` for performance improvements.
- Use `test:` for adding or correcting tests.
- Use `chore:` for build process, dependencies, or auxiliary tool changes.
- Append `!` after the type (e.g. `feat!:`) or include `BREAKING CHANGE:` in the footer for breaking changes (major version bump).
- Keep commit messages concise and imperative.
